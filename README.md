# 节点哨兵 NodeGuard 0.4.4

与 Clash Verge Rev 配合使用的 macOS 原生应用：监控 Claude/GPT 出口、自动恢复前置线路、保护 Claude 桌面端，并在网络空闲时测试当前订阅的全部前置节点。

Native macOS monitoring, failover and Claude service egress protection for Clash Verge Rev.

[下载安装包](https://github.com/lipanlp/NodeGuard/releases/latest) · [变更记录](CHANGELOG.md) · [参与开发](CONTRIBUTING.md) · [MIT 许可证](LICENSE)

## 拖动安装

从 [Releases](https://github.com/lipanlp/NodeGuard/releases/latest) 下载并打开 `NodeGuard-0.4.4-macOS-arm64.dmg`，将 NodeGuard.app 拖到旁边的 Applications 文件夹。若旧版已运行，先退出旧版，再从“应用程序”打开节点哨兵。用户设置保留，不用重新导入 Clash 配置。

窗口打开时显示 Dock 图标；关闭窗口后 Dock 图标隐藏，只保留顶部菜单栏入口，监控继续运行，从菜单栏「打开节点哨兵」重新打开窗口。退出应用会停止所有监控和自动化。启用严格保护时，菜单或 ⌘Q 退出需确认；脚本升级替换可发送 SIGTERM，应用会保存状态、停止候选核心后直接退出，并在事件中记录。窗口底部显示「版本 (构建号)」。

新安装默认启用监控和空闲全量测速。自动切换、Claude 强制退出和登录启动保留原设置，新用户默认关闭；本次升级不会自行武装保护或改动代理选择。

## 0.4.2 浏览器误判修复与探测含义

严格保护的实际连接检查仅针对 Claude 服务域名及其子域：claude.ai、claude.com、anthropic.com、claudeusercontent.com。Claude 内置浏览器访问第三方网站（例如开发预览站、GitHub、npm）按普通 Clash 分流，不因没有经过 Claude 专线而结束 Claude；未知域名/IP 请求也不单凭进程归属认定为 Claude 服务绕行。这不是对 Claude 包内所有互联网访问的出口强制限制。

Claude 服务域名的明确绕行、锁定 IP 偏离、国内出口和原有 TUN/进程识别检查继续生效。Claude Code/终端保护范围不扩大。

出口监控每次新建 HTTPS 连接，当前使用 8 秒建连/总请求预算（原先总请求 6 秒，建连被限制为 5 秒）。单次失败只表明该次探测未完成，不能单独证明所有既有连接断开：界面显示该次错误，但连续 2 次未通过才建立告警并通知，告警从第一次失败起计时并计入全部失败次数；未告警的单次失败恢复时不再发送「出口复验通过」。严格保护仍接收每一次失败并按原时限计时，到时限后进入「出口不通，保留 Claude」并请求更换前置，而不是结束 Claude。复验通知改为「出口复验通过」，时间明确为告警到复验的间隔，不称为真实断网时长。

域名依据：[Claude 官方网络控制说明](https://support.claude.com/en/articles/13065128-claude-in-chrome-admin-controls)。建连预算覆盖 DNS/TCP/TLS：[curl 官方说明](https://github.com/curl/curl/blob/master/docs/cmdline-opts/connect-timeout.md)。

## 故障备用与性能择优分别判断

断线恢复不再把「1 MB 上传超过 15 秒」视为不可用。最近 6 小时内有完整双向成功基线，并在提交前重新通过 Claude 连通、精确锁定 IP 和近期健康验证的候选，可用于断线救援；较慢候选不因此参与主动择优。缺少完整基线、IP 不符、国内出口、即时健康失败和过期证据仍不能授权切换。

当前上传较慢不会暂停备用健康维护。性能改善尝试未找到合格候选时，保留当前线路并回到周期复测，不持续占用恢复调度；备用重新就绪即结束旧「无备用」告警。排名和详情显示备用资格、健康待复验或过期原因。

真正断线时，会从当前订阅的全部授权候选中排序，并在排除冷却节点后选择本轮最多 5 个复验，不再被固定的 5 个展示候选卡住。提示会说明本轮可检查数量，不把一轮未通过说成全部订阅都不可用。手动备用模式仍只使用手动名单，写入前后 IP 校验和切换次数限制不变。

## 0.4.1 当前出口 IP 锁定

“锁定当前出口 IP”和“重新锁定当前出口 IP”适用于当前已验证出口。精确 IP 不变时，运营商标签或节点名称不是异常依据；国内出口、TUN/进程识别失效和实际连接路由不一致仍按原保护策略处理；出口仅仅不通时保留 Claude 并更换前置重试。升级保留已有 IP 与开关，首次按新出口上下文重测排名。

## 全部节点自动测试

- 启动或切换订阅后自动发现全部前置节点，不受备用勾选名单影响，也不再受旧版 12 个候选或每日 200 MB 限制。
- 默认网络低负载稳定 15 秒后串行测试；每个节点分别记录前置独立连通、出口、Claude/GPT 目标、小包上传与完整性能。主测速端点上传 1 MB、下载 2 MB；主端点失败会尝试 HTTPBingo 备用端点（500 KB 上传并折算为 1 MB 等效耗时、256 KiB 下载），均使用随机数据。每轮完成后间隔 6 小时重新测试，可在设置中改为 30 分钟至 24 小时。
- 使用 Mihomo 的连接与流量计数、物理网卡计数、当前 CPU 占用率和温度判断是否适合测速。不再把新建 AI 连接、心跳或零星请求当成忙碌。持续 6 秒超过门槛才让行；明显的大突发和严重温度限制立即让行。普通测试被中止后继续排队，不计为故障。
- 自己的出口探测按源端口识别，隔离测速核心的字节单独统计，从机器总流量中扣除，避免程序被自己的流量永久阻塞。
- 订阅 UID、实际节点定义或前置名单变化时，先取消旧任务，等待配置稳定，再重建队列。旧结果不能写入新订阅；排名按订阅和节点定义隔离，同名节点不会串用。
- UI 显示订阅、全量进度、等待/让行原因和其他网络流量。勾选节点可补充手动备用名单，不决定哪些节点会被测试。自动备用池从当前订阅内已验证的节点中维护 3–5 个候选，并按节点名称中的地区优先分散（不能据此证明上游相互独立）；维护备用不会自行开启切换。

后台约每 2 秒采样，发现活动后发出中止，curl 约每 0.1 秒检查取消。系统调度、API 延迟和未被完整观测的流量仍可能造成短暂竞争，不能保证完全零影响。长时间的大流量传输会顺延测试；普通聊天、小请求和后台心跳允许并行，不再无限重置等待。

## 0.3.0 的分层诊断、历史与续测

- 单个阶段失败不会抹掉已成功的 IP、请求耗时、目标连通或下载结果。详情页显示本地 DNS、本地代理连接、TLS、首字节、总耗时、字节数、HTTP 状态和错误分类；这些计时不等同于远端 DNS 或前置 TCP 握手计时。
- 三个以上不同节点在共享阶段出现相似失败时显示“疑似共同故障”；出口链路或跨线路的大上传共同失败时，性能负载暂缓 5 分钟，基础检查继续。不会把这种相关性称为根因已经确定。
- 大上传失败全部来自同一线路前缀（如「中转线路2-台湾01」「中转线路2-新加坡01」）时只提示该线路上游疑似异常，不暂缓其他节点；失败开始后已有其他节点通过同一大上传，则不判定为共享出口或测速服务故障。
- 队列完成只表示已检查所有节点；界面另列完整性能通过数量，性能暂缓会安排提前复测。
- 最近 24 小时最多 20 次完整测速计算真实成功比例，旧版的一条聚合结果只算一条可证实记录。健康复验和暂缓的性能项目不混入完整测速成功率。节点详情提供耗时散点图、P50、P95、标准差、最后完整成功时间和独立历史。
- 可按需执行 30 秒流式检查；它只验证这条代理链到公共测试端点的流式响应，不能代替真实 Claude/GPT 登录会话或 WebSocket 验证。
- 未完成队列与轮次原子保存，重启继续未完成节点。睡眠、唤醒、网络路径和地址变化会取消旧任务、丢弃过期证据，复验出口并重新等待低负载后续测；不修改 Wi-Fi、Clash 订阅或系统路由。
- 备用默认每 5 分钟做轻量健康复验，已有合格性能基线超过 1 小时时在低负载下刷新完整测速；没有合格基线的候选等待全量检测，不因维护任务反复占满性能测试。

## 测速避让模式

默认使用均衡模式。旧版默认的 60 秒等待自动迁移为 15 秒，其他自定义等待保留；IP 锁定、自动切换、严格保护开关保持原值。

| 模式 | 总上行 / 总下行门槛 | AI 上行 / AI 下行门槛 | CPU 门槛 |
| --- | --- | --- | --- |
| 保守 | 64 KB/s / 512 KB/s | 16 KB/s / 64 KB/s | 85% |
| 均衡 | 256 KB/s / 2 MB/s | 64 KB/s / 256 KB/s | 95% |
| 积极 | 1 MB/s / 8 MB/s | 256 KB/s / 1 MB/s | 98% |

门槛采用 1024 进制。一般负载连续达到门槛 6 秒才中止正在运行的测试；达到四倍门槛的大突发直接让行。观察到短暂峰值时可以暂缓开始下一个节点，但不会把整个低负载等待重置。CPU 使用系统 tick 差分采样，不再用滞后的 1 分钟 load average 代替当前占用。均衡和积极模式只在温度达到 critical 时立即暂停。

在“保护与自动切换 → 测速避让”选择模式。后台下载较多而仍希望测速时，可以使用积极模式；测试依旧单节点串行，保留大流量中止和温度保护。

## 出口监控与保护

| 功能 | 行为 |
| --- | --- |
| Claude/GPT 出口 | 分别请求 `claude.ai` / `chatgpt.com` 的 HTTPS trace，关联 Mihomo 的真实连接代理链，显示 IP、国家和时间。GPT 路线优先使用实际探测链，订阅没有同名 `ChatGPT` 策略组时仍可显示。 |
| 出口告警 | 连续 2 次探测失败、国内出口或无法确认时告警；不把验证码网页当作成功。国内判定采用 `loc=CN`。 |
| 前置自动恢复 | 仅管理已关联前置组的当前选择。手动名单或已启用的自动备用池必须有合格性能基线，并立即重新验证当前锁定 IP 和 Claude 目标；写入后再复验主路由。性能证据与健康证据保留各自时间，不伪造最近测速时间。故障恢复优先于普通全量队列。 |
| Claude 严格保护 | 先两次核对并由用户锁定具体出口 IP。确认 IP 偏离、国内出口、实际连接路由绕行或 Clash 不在规则/TUN/进程识别模式时，立即强制结束已识别的 Claude 桌面端和包内辅助进程。Clash 控制接口不可用、无法核对实际路由时默认最多复验 12 秒后结束，可在未武装时改为立即退出或 20 秒。出口探测仅仅失败（超时、TLS、连接失败）不结束 Claude：到时限后保持「出口不通，保留 Claude」，自动切换开启时先让出后台测速并更换前置重试，每次恢复尝试至少间隔 60 秒，仍受滚动切换预算限制；自动切换关闭时告警提示人工更换。本地源端口错误先在单次截止时间内换端口重试一次。Claude Code、Terminal、iTerm 不纳入。 |
| 性能排名 | 完整性能评分包含上传 45%、下载 20%、请求耗时 15%、真实成功比例 20%；部分通过保留阶段分，不能据此直接切换。不同测试端点结果在详情中分别标注。 |

锁定只保存确认时测得的具体出口 IP，不绑定运营商、住宅属性或节点名称。连续两次核对一致后展示 IP，用户确认时再次实测；如确认期间 IP 或路由改变，则保留原值并要求重新核对。IP 锁定不会因订阅或节点切换自动更新。

隔离测速动态复制当前 Claude 出口链，只替换已关联前置。未经过已关联前置组的出口仍可监控和锁定 IP，但前置测试和自动切换会暂停并说明原因。出口链或锁定 IP 改变后，测速结果按新上下文重新核验；旧历史保留，不能直接用来授权新出口切换。

路由和实际连接每 2 秒检查。出口常规每 15 秒，严格保护每 5 秒发起验证，单次网络超时 8 秒；证据超过 15 秒未更新时进入无法验证状态，再按选定时限复验；启动和唤醒同样先获取新证据。出口仅仅不通时 Claude 走同一条已断开的链路，不会经其他出口泄漏，因此保留 Claude 并恢复前置；一旦探测恢复，IP、国内出口和路由核对立即生效。Clash 控制接口持续不可用时仍会结束 Claude，界面会明确显示原因。

这是检测后结束进程的程序，无法拦截检测前的数据包，不能保证零泄漏。真正逐连接阻断需后续 Network Extension/System Extension 及相应签名和权限。

## 开启自动切换与严格保护

1. 保持 Clash Verge 规则模式、TUN 自动路由、进程识别开启。
2. 查看 Claude/GPT 最近一次实际探测和检查时间。
3. 点击“锁定当前出口 IP”，核对两次结果和真实链后确认具体地址。
4. 全量队列会自动测试；等待自动备用池出现就绪节点，或在排名中补充手动备用。
5. 分别开启自动切换、系统通知、严格保护；登录启动按需开启。

普通上传健康检查每 10 分钟进行，忙时让行；连续两次有明确上传网络失败证据或 1 MB 上传超过 15 秒才触发性能恢复。测速服务 HTTP 错误、本地错误和下载失败不会单独作为上传差的证据。故障节点冷却 30 分钟，性能故障切换间隔至少 10 分钟，连续断线恢复尝试至少间隔 60 秒。所有备用不合格时保留当前选择并告警。

## 0.4.0 自动择优与防抖

“前置节点自动管理”包含自动故障恢复和健康时自动择优；可单独关闭择优，只保留故障恢复。升级保留自动管理总开关，已开启总开关的用户会开始使用新择优策略，新安装总开关默认关闭。

- 仅比较当前订阅、精确锁定出口下的完整成功测速。当前节点和候选各至少两次、间隔至少 1 分钟、都在最近 30 分钟内；最多取三次中位数，且上传/下载端点一致。健康复验、性能暂缓、其他订阅和过期数据不补足样本数。候选最新完整检查失败就丢弃其旧优势。
- 候选综合分数须比当前高至少 10 分、同时提升至少 20%，并有实测收益：上传快至少 20%；或下载快至少 50% 且上传/耗时无明显退化；或请求耗时下降至少 40% 且上传无明显退化。评分接近时保留当前节点。
- 启动、换网、换订阅或切换节点后先稳定 3 分钟，同一候选优势再持续 3 分钟。决策每 30 秒重算；切换前必须通过即时出口和 Claude 健康复验，并重新核对分数、用户选择、订阅和低负载状态。
- 主动切换等待至少 20 秒未观察到明显 AI 数据传输（2 KiB/s 以上会重置）。心跳和程序自身探测不会永久阻塞。程序不会主动删除现有连接，但无法保证进行中的会话完全无感。
- 每次自动尝试后至少 30 分钟才允许再次主动择优，每小时最多 2 次择优尝试；刚离开的节点 60 分钟内不主动切回。检测到用户手动选择后暂停择优 30 分钟，故障恢复继续。
- 所有自动提交与回退都记入滚动一小时预算，达到 4 次后停止新切换并告警。已开始的切换如复验失败仍优先安全回退，回退也计数，因此必要回退可能使记录超过 4 次。失败和待确认操作也计数，重启、订阅变更不会清空限制。
- 在低负载下为当前节点和排名靠前的三个合格候选补足完整样本，整体及单节点完整补测最短间隔均为 2 分钟；已有新鲜样本不重复测，15 分钟后再刷新。全部前置节点的定期全量测试仍继续。

切换记录保存在本机状态中；脱敏诊断仅导出匿名节点、时间、原因和结果。

Mihomo 没有原子 compare-and-swap。程序在写入前重读、检查取消令牌，写后复验；订阅变更时不向新订阅回滚旧选择，仍不能消除 API 读写之间极短的竞态。已进行的上传无法无缝迁移到新线路。

## 适配、资源与隐私

Apple Silicon，macOS 13+；本机以 macOS 26.5.2、Clash Verge Rev 2.5.8、Mihomo 1.19.32 验证。当前使用 Ad Hoc 本地签名，未作 Developer ID 公证；其他 macOS 和 Intel 尚未实机验收。

默认关联前置组 `KTM前置节点`、Claude 组 `Claude专线` 和 GPT 组 `ChatGPT`。需要与现有 Clash 配置匹配；更换这些组名时可在退出程序后修改本机状态文件中的 `frontGroup`、`claudeGroup`、`gptGroup`，保留其他字段并先备份。

适配 `/Applications/Claude.app`、`/Applications/Clash Verge.app`，以及当前用户的 Clash Verge Unix 控制接口和生成配置。订阅若没有可关联的前置组，程序等待并显示原因；外部 proxy-provider 中未展开的定义暂不支持隔离测试，会明确记录失败，不伪造分数。

原生 SwiftUI/AppKit/Charts，无 Electron、浏览器或 Python 运行时，不附带第二份 Mihomo。普通采样使用本机 Unix socket 和轻量网卡计数，只有一个测速核心；其 TUN 关闭、绑定物理网卡，仅本机监听，并使用临时认证。控制接口在 0700 私有目录内。测试结束立即停止核心并删除私密配置；启动时清理已确认属于自身的遗留测试会话。

目录 0700，状态和临时配置 0600。仅保留 200 条事件、有限的合并事件和最多 4000 条独立历史样本，采用后台合并原子写入，并保留上一份有效状态以恢复损坏文件。凭据不进入命令行、事件、报告或交付包；上传的是随机测试数据。流量不设默认限额，UI 显示保守预估量，取消或失败也计入预留量。

设置与事件：`~/Library/Application Support/NodeGuard/state.json`。本次升级前备份：`state.before-v0.4.2.json`；自动恢复副本为 `state.previous.json`。临时目录：`~/Library/Caches/NodeGuard/Probes/`。不修改 Clash 的订阅、扩展脚本、DNS 或规则。

## 通知与脱敏诊断

首页分别展示控制接口、出口证据、保护武装、备用就绪和通知权限。普通错误按事件身份合并，记录首次/最近时间、次数、发生时前置、持续时长和恢复。严重升级立即提醒，持续普通事件每 15 分钟提醒一次；订阅/前置上下文变化单独结束旧事件，不冒称网络恢复。

“允许系统通知”申请 macOS 权限。“发送测试通知”会立即显示应用内反馈，3 秒后请求系统横幅和声音，再查询通知中心回执；区分提交失败、系统已收件和未确认展示，12 秒仍无结果会结束等待。窗口处于前台时也通过通知代理请求展示，修复旧版前台默认静默的问题。通知中心收件不能证明用户看见横幅；专注模式、屏幕镜像/共享时关闭通知等 macOS 设置仍可能抑制展示，程序不会修改这些全局设置。依据：[Apple 本地通知与前台展示](https://developer.apple.com/library/archive/documentation/NetworkingInternet/Conceptual/RemoteNotificationsPG/SchedulingandHandlingLocalNotifications.html)。

首页或事件页可导出 JSON 诊断。采用字段允许列表：节点匿名化，保留阶段、错误码和计时，移除 IP、节点名称、订阅 URL、密钥、原始配置、原始错误/事件文本、本地路径及会话内容。默认只保存到用户选择的本地文件，不上传。

配置与认证解析按文件变更缓存，出口探测共享有界的连接表采样；关闭/遮挡窗口后减少界面发布，监控时钟与界面刷新分开。监控期间使用允许电脑正常睡眠的活动声明维持定时器，睡眠时释放，不强制电脑常亮或禁止睡眠。

## 构建与验证

需要 macOS 和 Apple Command Line Tools（`xcode-select --install`）。应用不需要 Python；运行假 API 集成测试时需要 Python 3。

```sh
git clone https://github.com/lipanlp/NodeGuard.git
cd NodeGuard
```

依赖源码已附带，来源见 [第三方组件](docs/THIRD-PARTY.md)。

```sh
./scripts/build.sh
./scripts/test.sh
python3 scripts/mock-api-test.py
work/build-arm64/NodeGuardTests --live-cancellation
./scripts/package.sh
python3 scripts/verify-dmg.py
outputs/NodeGuard.app/Contents/MacOS/NodeGuard --diagnose
outputs/NodeGuard.app/Contents/MacOS/NodeGuard --export-diagnostics work/redacted.json
open -n outputs/NodeGuard.app --args --observe-only
```

`--observe-only` 使用真实状态，但不保存设置、不自动测速、不换节点、不结束进程、不注册登录启动。真实核心取消验证只启动隔离核心并在网络载荷前取消；其他进程结束与切换测试使用模拟执行器和临时假 API。

构建脚本直接使用 Command Line Tools，避开本机 SwiftPM SDK PlatformPath 查询问题。完整源码也附带 `Package.swift`，本机未验证 SwiftPM 构建路径。
