# 项目设计

节点哨兵使用 SwiftUI/AppKit 构建 macOS 原生界面，与本机 Clash Verge Rev 的 Mihomo 核心及 Unix 控制接口协作。当前公开版本为 0.4.2。

## 功能范围

- 分别监控 Claude/GPT 的实际 HTTPS 出口 IP、国家、检查时间与连接代理链。
- 在低负载时串行测试当前订阅全部前置节点，订阅或出口上下文变化后重新核验。
- 管理故障备用和健康时的自动择优，保留手动选择、冷却与滚动次数限制。
- 按用户确认的具体 IP 保护 Claude 服务出口。内置浏览器的第三方网页不按 Claude 专线校验；Claude Code 和终端不在进程结束范围内。
- 提供本机通知、历史、事件、图表及允许列表脱敏诊断，不接入外部消息推送。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `MonitorModel` | 监控、探测、备用维护、全量队列与恢复调度 |
| `MihomoClient` | Unix HTTP 状态读取、前置选择提交及结果复核 |
| `Probe` / `DiagnosticRunner` | 有时限 HTTPS 探测、分层结果与错误分类 |
| `CandidateProbe` | 临时认证、关闭 TUN、绑定物理接口的隔离测速核心 |
| `ExitRoute` / `ClaudeServiceScope` | 当前出口链解析与 Claude 服务域名范围 |
| `ProtectionPolicy` / `StrictProtectionMachine` | 路由、精确 IP 与无法验证时限判断 |
| `BackupPlanner` / `BestNodeTracker` | 故障备用、性能证据与择优防抖 |
| `ProcessGuard` | 所有权、应用包路径、PID 身份复核及可注入信号发送器 |
| `StateWriter` / `NetworkLifecycle` | 后台原子保存、损坏恢复、睡眠与网络事件处理 |

## 约束

1. IP 只有用户明确确认才能更新，不从变化后的出口自动学习。
2. 备用需要有效性能基线、即时健康与精确 IP 证明；切换后再次验证主路由。
3. 较慢节点可以用于真正断线的救援，不能因此当成健康状态下的最优节点。
4. 每次提交前重读状态，核对订阅、当前选择和取消令牌。Mihomo 没有原子 compare-and-swap，仍存在短暂外部并发修改窗口。
5. 不删除既有连接，不覆盖 Clash 订阅、代理定义、脚本、DNS 或规则。
6. 不把单次探测超时视为所有业务连接中断；通知收件与用户看见横幅也分别报告。
7. 真实切换与进程结束由独立开关控制，默认关闭。只读模式不保存设置、不执行自动化和结束进程。

## 验证方式

构建、核心测试、假 API/信号和安装包核验见 [参与开发](../CONTRIBUTING.md)。源码中的测试使用示例域名、文档保留 IP 与明显的假凭据。

开发验证不能通过切换真实前置或结束真实 Claude 来制造成功结果。真实故障恢复、严格保护、睡眠、网络更换、登录启动与长时间运行须在独立环境另外验收。

严格保护是检测后退出机制，不能拦截检测前的数据包，也不保证现有会话无感迁移。逐包限制需要单独的 Network Extension/System Extension 方案与相应签名和权限。
